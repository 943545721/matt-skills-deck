# 需求票 ↔ 地图票：补一条真正的引用边

## 目标
让「这张地图是从哪条需求长出来的」成为数据里存在的事实，而不是只写在正文散文里。

## 非目标
- 不做跨仓库版本（`owner/repo#N`），先只认本仓库票号。
- 不动板子的分组规则：需求票不缩进到地图下面（那是「归属」，方向相反）。
- 不引入新后端字段：GitHub 没有「衍生自」原生关系。

## 方案
1. 边存在**地图票正文**的一行：`Derived from: #19`（与既有的 `Blocked by:` 同一套做法）。
   - 解析：`shared/derived.ts`（纯函数 + 单测）。
2. `issueSummary` 增加 `derivedFrom?: number | null`：正文读得到时才算，读不到就缺省。
3. 反查（需求 → 它长出的地图）：`server/tracker/derived.ts` 读一遍带正文的地图票，
   比 `derivedFrom`。只在打开一张非地图票的详情时跑，失败返回空表 + 原因，不拦详情。
4. 写入：`deck_map_plan_create` 增加 `sourceIssue`：
   - 建图时把这一行写进地图正文（建票时就带上，不做二次改正文）；
   - 在需求票上留一条评论说明「建了地图 #N」（GitHub 没有反向边，评论是唯一跨票可见的痕迹）。
5. 显示：票面详情两块——地图看「来自需求 #N」，需求看「关联地图 #N」，都能点过去。

## 阶段
A. 纯函数 + 单测 → B. 契约字段 + 三种后端填值 → C. 反查 + 详情 RPC →
D. 建图工具入参 → E. 界面两块 → F. 文档与图纸同步。

## 测试
`tests/derived.test.mjs`：解析、覆盖写入、非法值、无这一行。
反查与写入靠 typecheck + 手工读回（本机无远端写权限时只验计划分支）。

## 风险 / 回滚
- 正文多一行：地图五区块解析按 `##` 切，标题前多一行不影响（要在测试里钉住）。
- 用户手改这行会导致反查与正文不一致：以地图正文为准，需求侧不做缓存。
