# 文档影响检查

检查本次改动是否让现有文档过时。输入应是当前工作区的改动或用户指定的 diff；不要假定代码就是正确规格。

## 检查步骤

1. 查看本次改动的文件和关键行为，并找到与这些行为直接相关的文档、规格、ADR、词汇表和 `AGENTS.md` 规则。优先沿代码中的文档链接、测试名称和已有文档索引查找，不要无差别重写全仓库文档。
2. 对照需求、已确认决定、测试和实现，判断每段相关文档属于哪类：
   - **当前实现说明**：描述现在实际行为；若需求和测试已确认新行为，只是文字没跟上，应同步修改。
   - **有效规则或决定**：ADR、用户确认的约束、规范或规格；若它与代码冲突，不要按代码静默改文档，也不要自行断定代码正确。报告冲突和证据，交给用户决定。
   - **历史记录**：保留当时方案和时间背景；若已过时，标明已被什么决定取代，不抹去历史。
3. 如果这次改动没有影响文档，明确记为「检查过，无需更新」，并说明检查了哪些相关文档。
4. 只同步有明确依据的内容。不要为了让文档看起来一致而编造产品行为、伪造验证结果，或扩大本次改动范围。
5. 汇报检查结论：更新了哪些文档、哪些无需改、发现了什么待用户决定的冲突。冲突未解决时，不要声称文档已完全同步。

## 边界

- 不把本技能当成自动事实源：代码、测试和文档不一致时，必须回到需求或已确认决定查证。
- 不把 ADR、规范、用户决定改写成“代码现状”；先报告冲突。
- 不要求为了每次代码改动都增加文档；检查后可以合理地判定无需更新。
- 不提交、不推送、不发布。
