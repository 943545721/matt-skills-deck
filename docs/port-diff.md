# 与 DSH 版的逐项对照

源仓库：[FeatherHunter/dsh-mattpocock-skills-deck](https://github.com/FeatherHunter/dsh-mattpocock-skills-deck)（DSH CLI 插件）。
本仓库是同一套产品思路的 **Paseo 0.13 插件**。两边宿主能提供的面不一样，所以差异分三类：

- **照搬语义**：数据怎么读、怎么排、怎么解析，与源仓库同口径，改口径会让两边对同一张票给出不同结论。
- **换面实现**：功能在，但落到了 Paseo 有的面上（标签页、弹窗、剪贴板、MCP 工具）。
- **不做**：宿主没有对应能力，或不值得为此造一个假的替代品；原因写清楚。

## 能力对照

| DSH 版 | 本插件 | 类别 |
|---|---|---|
| 侧栏常驻任务面板：地图票、普通票、可接/已关闭 | 工作区标签页面板（可与 Agent、终端并排），同口径排序 | 换面 |
| 列表行「一键注入 prompt」到对话框 | 复制到剪贴板 + 提示（插件改不了 Agent 输入框） | 换面 |
| 对话框胶囊栏：可接任务、故障、需诊断、刷新、处理路径表 | **未做**：0.13 的 `addComposerPill` 必须按 `agentId` 注册，客户端拿不到 agent 列表；等平台给列表或事件 | 不做 |
| 「工作路线」= 当前会话处理的 ISSUE 心路历程 | 地图页的工作路线：按 `wayfinder:*` 标签排序的路线票（会话维度拿不到，改用票面维度） | 换面 |
| 新增需求引导：探索/实施二选一，六步初始化 | 只保留「新建票」（含「标记为地图」），不做流程向导 | 不做 |
| 技能面板：27 技能、看原文、注入对话框、技能详情 | 技能页：27 技能中英双语、技能详情、按工作区安装到 `.claude/skills` 与 `.agents/skills`；「注入对话框」换成「复制技能原文」 | 照搬 + 换面 |
| 多后端切换：GitHub / 本地 Markdown / GitLab，环境逐项自检 | **只接 GitHub**（读写都是）；诊断页只给环境读数与操作日志，不做后端切换 | 不做（有闸门） |
| 版本管理：fetch/pull/push/add/commit、提交历史、工作树 | 同左，外加「按票提交」流程（暂存 → 预检 → 提交 → 同票重放被拒）；没有提交历史列表 | 照搬 |
| 设置与外观：按标签配色改按钮颜色，独立设置页 | 标签配色页直接改 GitHub 标签颜色并即时换算可读文字色；不设独立设置页，界面语言跟随 App | 照搬 + 简化 |
| 会话自动命名（规则截取） | **不做**：`agent.create` 钩子看不到首条提示词，也没有改名 API | 不做 |
| Agent 工具：`src/deck/tools/*`（下一步建议由模型生成，2–4 条，prompt ≤500 字） | 7 个 `deck_*` MCP 工具；下一步建议改为**纯规则**，最多 3 条，不调模型 | 换面 + 简化 |
| 自定义 CSS 的卡片视觉 | RN 原语重画：直角、2px 描边、右下 3px 硬投影、等宽数字；触屏端按钮抬到 40pt | 换面 |

## 照搬过来的语义（改了就是 bug）

- 规范标签与颜色：`bug` `needs-triage` `needs-info` `ready-for-agent` `ready-for-human` `wayfinder:grilling` `wayfinder:map` `wayfinder:prototype` `wayfinder:research` `wayfinder:task`。
- 地图正文五个区块：`Destination` / `Notes` / `Decisions so far` / `Not yet specified` / `Out of scope`；`##` 与标题之间没有空格也算标题；粘在上一行末尾的标题会被切开；围栏代码块里的不动。
- 决策行两种写法：`- [标题](链接) — 一句话` 与 `- **标题**：一句话`；加粗写法里 `[#1057](链接)` 只留票号当标题。
- 决策那句话超 240 字就退到最后一个完整词再加省略号。
- 雾与「不做」里的 HTML 注释行不进界面，其余行（含 `- ` 符号）原样保留。
- 路线只收 `wayfinder:research|prototype|grilling|task`，**剔除地图票自己**；开着的排在关掉的前面，同类按票号升序。
- 建议按「先目标、再雾、再研究/讨论/原型/任务」的次序给。

## 没搬的部分与原因

- **多后端**：GitLab 与本地 Markdown 的读写都没接。写路径尤其需要闸门——GitLab 的写接口没实现时若放行，用户会看到「成功」而远端什么也没发生。
- **流程向导**：「探索 / 实施」二选一 + 六步初始化是 DSH 特有的工作流外壳，Paseo 没有对应的承载面，硬搬到标签页里只会变成一屏的说明文字。
- **注入到对话框**：Paseo 插件拿不到 Agent 的输入框，只能产出文本由用户粘贴。
- **模型生成建议**：源仓库的建议由模型生成（2–4 条、限制各自长度与优先级），这里改成纯规则码（理由 + 提示词模板在前端按语言组装），因为插件不该在每次读地图时额外烧一次模型调用；需要模型判断时，复制提示词交给会话里的 Agent 更直接。
